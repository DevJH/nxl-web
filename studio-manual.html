NextLab Studio
사용자 메뉴얼

아이디어에서 기획 · 디자인 · 코드까지 잇는 데스크톱 AI 에이전트 워크스페이스의 사용 설명서입니다. 2장 Launchpad 가 이 도구의 주 기능이며, 이 문서의 절반을 차지합니다. Figma 링크가 이미 있다면 3장부터 읽어도 됩니다.

앱 v0.1.1 Windows · macOS 설치형 Launchpad · Figma to Code DS 자산 내장
표기
이 문서의 표기 규칙 Cmd 는 macOS 기준이며 Windows 에서는 Ctrl 로 읽습니다. 이런 글자 는 화면에 그대로 보이는 값·경로·명령입니다. [필수] 표시가 붙은 단계는 건너뛰면 기능이 동작하지 않습니다.
범위
이 문서는 개발이 완료되어 지금 쓸 수 있는 기능만 다룹니다. 기획·디자인 트랙(Launchpad)과 엔지니어링 트랙(Figma to Code)이 대상입니다. FE·BE·클라우드·아키텍처·보안·WBS 표준 에이전트 6종은 컨셉 단계로 순차 추가되며, 확정되는 대로 이 메뉴얼에 장을 더합니다.

CHAPTER 01

설치와 첫 실행

Studio 는 VSCode 확장이 아니라 독립 실행되는 데스크톱 앱입니다. 한화 DS 디자인 자산이 앱 안에 내장되어 있어, Figma 를 쓸 수 없는 외부 SI·오프라인 환경에서도 화면을 만들 수 있습니다.

1.1설치

사내 배포 채널에서 사용하는 OS 의 설치 파일을 내려받습니다.

OS설치 파일요건
Windows NextLab.Studio.Setup.0.1.1.exe Windows 10 이상 · x64내려받아 실행하면 설치 마법사가 진행됩니다
macOS (Apple Silicon) NextLab.Studio-0.1.1-arm64.dmg macOS 13 이상 · M1 이후dmg 를 열고 앱을 응용 프로그램 으로 끌어 넣습니다
macOS (Intel) NextLab.Studio-0.1.1.dmg macOS 13 이상 · x64Intel Mac 은 이 파일을 받습니다 — arm64 판은 실행되지 않습니다
  1. 설치 파일을 실행해 안내대로 설치를 마칩니다
  2. 첫 실행은 OS 가 한 번 막습니다 — 아래 안내대로 허용합니다
  3. Studio 를 실행합니다 — 최초 실행은 내장 자산을 펼치느라 몇 초 더 걸립니다
  4. 좌측 사이드바에 네 구역이 보이면 설치 완료입니다 (1.3)
첫 실행
"악성 코드가 없음을 확인할 수 없습니다" 는 고장이 아닙니다. 아직 서명·공증(notarization)이 적용되지 않아 OS 가 사내 배포본을 처음 한 번 막는 것입니다. 서명이 적용되면 이 절차는 사라집니다. 아래는 그때까지의 임시 절차이며, 최초 1회만 하면 됩니다.

macOS — 차단 창을 닫고, 시스템 설정 → 개인정보 보호 및 보안 으로 가서 아래쪽에 나타난 "그래도 열기" 를 누릅니다. (Sequoia 부터는 우클릭 → 열기로 우회할 수 없습니다.)
Windows — SmartScreen 파란 창에서 추가 정보 → 실행 을 누릅니다.
사전 조건
AI CLI 가 PC 에 설치되어 있어야 합니다. Studio 는 공용 API 키가 아니라 각자의 AI 계정으로 실행됩니다. Claude 를 쓰려면 claude 명령이 필요하며, 미설치 시 npm install -g @anthropic-ai/claude-code 로 설치합니다.

1.2AI 계정 연동 필수

연동을 마치기 전에는 Launchpad · Figma to Code 가 실행되지 않습니다. 최초 1회만 하면 됩니다.

  1. 좌측 사이드바 하단의 계정 을 엽니다
  2. 연동 상태를 확인합니다 — ✓ 는 연동됨, ! 는 미연동입니다
  3. 미연동 항목을 클릭하면 로그인 절차가 시작됩니다
  4. 로그인을 마치고 돌아오면 표시가 ✓ 로 바뀝니다
보안
로그인 토큰은 이 PC 를 벗어나지 않습니다. OAuth 토큰은 OS 키체인(macOS 키체인 · Windows 자격 증명 관리자)에 암호화되어 저장되며, NEXTLAB 이 운영하는 서버로 전송되지 않습니다. Studio 는 공용 API 키가 아니라 각자의 AI 계정으로 실행되므로, 사용량만큼 비용이 발생합니다.

1.3화면 구성

좌측 사이드바는 네 구역입니다. 무엇을 만들지(기획·디자인 / 엔지니어링)와 무엇으로 만들지(에이전트 / 라이브러리)가 나뉘어 있습니다.

구역하는 일참조
기획 · 디자인Launchpad — 아이디어에서 PRD · 화면 흐름 · 실물 화면까지2장
엔지니어링Figma to Code — 디자인 링크에서 NXL 표준 React 코드 생성3장
에이전트대화 상대를 고릅니다. 고르면 연결된 스킬·메뉴얼이 컨텍스트로 자동 주입됩니다—
라이브러리스킬과 사내 정본 메뉴얼이 보관되는 곳입니다—
개념
에이전트를 먼저 고르고 대화를 시작합니다. 에이전트는 단순한 말투 프리셋이 아니라, 어떤 규칙 문서를 읽고 답할지를 정하는 스위치입니다. FE 표준 에이전트를 고르면 NXL FE 개발표준이, 기획 에이전트를 고르면 기획 가이드가 컨텍스트에 들어갑니다.

CHAPTER 02 · 주 기능

Launchpad — 0 to 1

아이디어만 있고 기획서도 디자인도 없는 상태에서 시작하는 기능입니다. 세 기능의 묶음이 아니라 하나로 연결된 파이프라인이라는 점이 핵심입니다 — 앞 단계의 산출물이 뒷 단계의 입력이 되므로, 순서대로 진행할 때 가장 잘 동작합니다.

2.0전체 흐름 한눈에

INPUT아이디어 한 줄과 도메인 지식 — 기획 양식은 몰라도 됩니다
STEP 1Talk to Spec — 되묻는 질문으로 빠진 요건을 채워 PRD · 기능명세 도출
STEP 2User Flow — 도출된 기획으로 화면 간 흐름도 자동 배치, 예외 경로 포함
STEP 3Talk to Design — 내장 캔버스에 사내 디자인 킷으로 실물 React 화면 렌더
OUTPUT기획 문서 · 화면 흐름도 · 동작하는 MVP 화면
권장
한 번에 완성하려 하지 마세요. 각 단계에서 결과를 검토하고 고친 뒤 다음 단계로 넘기는 편이 훨씬 빠릅니다. 1단계 기획이 어긋난 채로 3단계까지 가면, 화면을 다시 만드는 비용이 더 큽니다.

2.1Talk to Spec — 기획 도출

기획 양식을 몰라도 됩니다. 아이디어를 입력하면 LLM 이 되묻는 질문으로 빠진 요건을 채우고, PRD → 유저플로우 → 와이어프레임 방향을 순서대로 도출합니다.

  1. 사이드바 기획 · 디자인 → Talk to Spec 을 엽니다
  2. 만들려는 것을 평소 말투로 적습니다 — "현장 작업자가 설비 점검 결과를 모바일로 올리는 화면" 정도면 충분합니다
  3. 되묻는 질문에 답합니다. 모르는 항목은 모른다고 답해도 진행됩니다 — 가정으로 채우고 표시해 둡니다
  4. 도출된 PRD · 기능명세를 검토하고, 어긋난 부분은 대화로 고칩니다
  5. 확정되면 다음 단계로 보내기 로 User Flow 에 넘깁니다

잘 나오게 하는 입력

  • 누가 쓰는지를 먼저 적습니다 — 사용자가 정해지면 나머지 질문이 구체적으로 바뀝니다
  • 도메인 용어를 그대로 씁니다. 일반적인 말로 바꿔 적으면 그만큼 일반적인 기획이 나옵니다
  • 이미 정해진 제약(사용 기기 · 오프라인 여부 · 기존 시스템 연계)은 처음에 적어 둡니다
활용
기획을 역으로 도출할 수도 있습니다. 이미 화면이나 요구사항 메모가 있는 경우, 그것을 붙여 넣으면 빠진 요건과 예외 케이스를 짚어 구조화된 기획서 형태로 정리해 줍니다. 디자이너·개발자가 도메인을 모를 때 쓰는 방식입니다.

2.2User Flow — 화면 흐름도

도출된 기획을 바탕으로 화면 간 흐름을 자동 배치합니다. 정상 흐름과 오류·예외 흐름이 톤으로 구분되어, 빠진 경로를 그 자리에서 찾아낼 수 있습니다.

  1. Talk to Spec 에서 넘어오면 흐름도가 자동으로 그려진 상태로 열립니다
  2. 노드를 끌어 배치를 정리합니다 — 위치는 결과물에 영향을 주지 않고 읽기 편하라고 있는 것입니다
  3. 노드를 클릭해 화면 이름 · 역할 · 진입 조건을 수정합니다
  4. 빠진 경로는 대화로 추가합니다 — "결제 실패했을 때 흐름을 넣어줘" 처럼 적으면 노드와 연결선이 함께 생깁니다
  5. 확정되면 다음 단계로 보내기 로 Talk to Design 에 넘깁니다

이 단계에서 꼭 확인할 것

  • 모든 화면에 들어오는 경로가 하나 이상 있는지 — 고립된 노드는 대개 기획 누락입니다
  • 오류 · 빈 상태 · 권한 없음 경로가 있는지
  • 되돌아가는 경로(취소 · 뒤로)가 끊기지 않는지

2.3Talk to Design — 실물 화면

내장 캔버스에서 사내 디자인 킷으로 실물 React 화면이 렌더됩니다. 그림 목업이 아니라 동작하는 화면이므로, 그대로 흐름을 눌러 보며 검증할 수 있습니다.

  1. User Flow 에서 넘어오면 화면 목록이 만들어지고, 첫 화면이 캔버스에 렌더됩니다
  2. 디자이너가 아니어도 요소를 직접 끌어 위치를 바꾸고 간격 · 정렬 · 색을 다듬습니다
  3. 구조를 바꾸는 수정은 대화로 지시합니다 — "목록을 카드에서 표로 바꿔줘"
  4. 화면 목록에서 다음 화면으로 옮겨 같은 방식으로 다듬습니다
주의
여기서 나온 화면은 MVP · 검증용 초안입니다. 디자인 킷을 쓰므로 색·간격은 표준을 따르지만, 실제 데이터 연동과 예외 처리는 들어 있지 않습니다. 운영에 올릴 코드로 만들려면 3장 Figma to Code 나 Builder 로 이어서 작업하세요.

CHAPTER 03

Figma to Code

이미 Figma 디자인이 있다면 Launchpad 를 건너뛰고 여기서 시작합니다. 디자인 링크에서 한화 DS 표준 React 코드를 생성합니다.

  1. 사이드바 엔지니어링 → Figma to Code 를 엽니다
  2. Figma 에서 변환할 프레임을 선택하고 우클릭 → Copy link to selection 으로 링크를 복사합니다
  3. 복사한 링크를 붙여 넣습니다 — 주소에 ?node-id=… 가 포함되어 있어야 합니다
  4. 디자인시스템과 대상 경로를 고르고 실행합니다
  5. 생성된 코드를 미리보기로 원본과 대조하고, 어긋난 부분은 대화로 보정합니다
// 링크에 node-id 가 있어야 특정 프레임을 정확히 읽습니다
https://www.figma.com/design/<fileKey>/파일이름?node-id=684-16571&m=dev
차이
Builder 와 같은 엔진, 다른 실행 환경입니다. VSCode 안에서 프로젝트에 바로 적용하며 쓰려면 NEXTLAB Builder 를, 에디터 없이 기획·디자인과 이어서 쓰려면 Studio 를 씁니다. 옵션·검증 루프·산출물 적용 등 상세한 내용은 Builder 메뉴얼 2장 을 참조하세요.
전제
사람 검수를 전제로 한 도구입니다. AI 특성상 미세한 색·여백 차이는 남을 수 있습니다. 생성물은 미리보기로 원본과 대조하고, 어긋난 부분을 보정한 뒤 사용하세요.

CHAPTER 04

문제 해결

증상원인과 해결
앱이 안 열림 — "악성 코드가 없음을 확인할 수 없습니다" 서명·공증 전이라 OS 가 첫 실행을 막는 것입니다. macOS 는 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기", Windows 는 SmartScreen 에서 추가 정보 → 실행. 최초 1회만 필요합니다. (1.1)
Mac 에서 앱이 손상됐다고 나옴 칩에 맞지 않는 설치 파일입니다. Apple Silicon 은 arm64.dmg, Intel 은 NextLab.Studio-0.1.1.dmg 를 받으세요. (1.1)
기능을 눌러도 실행되지 않음 AI 계정이 연동되지 않은 상태입니다. 계정 에서 ! 표시를 클릭해 로그인하세요. (1.2)
연동 표시가 계속 ! CLI 로그인이 만료되었거나 CLI 가 설치되지 않은 경우입니다. claude 명령이 터미널에서 동작하는지 확인한 뒤 다시 로그인하세요. (1.1 · 1.2)
기획이 두루뭉술하게 나옴 입력이 일반적일수록 결과도 일반적입니다. 사용자·도메인 용어·제약을 구체적으로 적고, 되묻는 질문에 답해 요건을 채우세요. (2.1)
흐름도에 예외 경로가 없음 기획 단계에서 예외가 정의되지 않았습니다. 흐름도에서 대화로 "실패했을 때 흐름을 넣어줘" 처럼 추가하면 노드와 연결선이 함께 생성됩니다. (2.2)
캔버스 화면이 의도와 다름 구조 변경은 끌어 옮기기가 아니라 대화로 지시해야 합니다. 간격·정렬·색만 직접 다듬으세요. (2.3)
엉뚱한 화면이 생성됨 (Figma to Code) 링크에 node-id 가 없습니다. 프레임을 선택하고 우클릭 → Copy link to selection 으로 다시 복사하세요. (3장)
실행이 도중에 멈춤 도구 권한이 표준 이면 확인 단계에서 대기할 수 있습니다. 전체 허용 으로 바꾸면 중단 없이 완주합니다.
전제
사람 검수를 전제로 한 도구입니다. Studio 는 0 에서 1 까지를 빠르게 만들어 검증을 앞당기는 도구이지, 기획·디자인 검토를 없애는 도구가 아닙니다. 각 단계의 산출물은 다음 단계로 넘기기 전에 확인하세요.
NextLab Studio 사용자 메뉴얼 v1.0 · 앱 v0.1.1 사내 전용 — 외부 공유 금지 · 2026
