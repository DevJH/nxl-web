                      1개요

                      NXL-DS Hanwha 는 한화생명 고객 서비스 화면용 React 컴포넌트 라이브러리다. 디자이너의 Figma Component Library(NXL-DS)를 정본으로 삼아 컴포넌트·토큰·아이콘·그래픽을 제공하고, 화면 폭에 따른 전환(Mobile·Tablet·PC)을 컴포넌트와 토큰 수준에서 처리한다. 이 문서는 0.9.0 기준이다.

                      문서의 수치(파일 크기, 번들 크기, 색 대비, 시험 개수)는 0.9.0 배포물을 직접 재서 적었고, 측정 방법을 표 아래에 함께 둔다. 예시 코드는 모두 0.9.0 타입 선언에 strict 모드로 컴파일해 확인했다. 구조를 이렇게 정한 이유와 그 비용은 12장에 모았다.

                      1.5전체 구조

                      토큰과 컴포넌트는 Figma 에서 출발해 두 경로로 앱에 닿는다. CSS 경로는 Figma Variables 를 CSS 변수로 생성하고 Tailwind 로 한 번 컴파일해 styles.css 한 파일로 만든다. JS 경로는 Figma 컴포넌트 속성을 props 로 옮긴 소스를 모듈별 ESM 으로 빌드한다. 생성된 파일은 손으로 고치지 않으며, 값이 바뀌면 생성기를 다시 돌린다.

                      2설치와 초기 설정

                      패키지 설치부터 첫 화면까지의 설정이다. 2.1~2.4 를 순서대로 하면 DS 컴포넌트가 화면에 나온다. Next.js 는 2.5, 테스트는 2.6 을 함께 본다.

                      2.1패키지 설치

                      0.9.0 은 tgz 로 배포한다. 사내 Nexus 등록 후에는 레지스트리 설치로 바뀌지만 import 경로는 같다.

                      Shell

pnpm add ./vendor/nextlab-ds-0.9.0.tgz

# 사내 Nexus 등록 후
pnpm add @nextlab/ds

# Tailwind CSS v4
pnpm add -D tailwindcss @tailwindcss/postcss   # Next.js
pnpm add -D tailwindcss @tailwindcss/vite      # Vite

                      tgz 파일과 잠금 파일을 함께 커밋해 설치 결과를 고정한다. Tailwind 설정 파일은 Tailwind 공식 설치 문서를 따른다.

                      2.2CSS

                      CSS
                      /* src/app/globals.css (Vite: src/index.css) */
@import 'tailwindcss';
@import '@nextlab/ds/hanwha/styles.css';

                      styles.css 는 컴포넌트 스타일, 디자인 토큰, 토큰 유틸리티를 한 파일로 미리 빌드한 것이다. 앱의 Tailwind 설정에 DS 토큰을 등록하지 않아도 bg-bg-layer-base, type-body-medium 같은 클래스가 동작한다. 구조는 3장에서 설명한다.

                      2.3폰트

                      DS CSS 는 HanwhaGothic(300·400·700)을 /fonts/HanwhaGothic{L,R,B}.woff2 경로로 선언한다. 한화 폰트 CDN 의 파일을 이 경로에 둔다.

                      Shell
                      mkdir -p public/fonts
CDN=https://nxl-nlc.hanwhalife.com/cnts-files/fonts/HanwhaGothic
curl -o public/fonts/HanwhaGothicL.woff2 $CDN/06HanwhaGothicL.woff2   # 300
curl -o public/fonts/HanwhaGothicR.woff2 $CDN/05HanwhaGothicR.woff2   # 400
curl -o public/fonts/HanwhaGothicB.woff2 $CDN/04HanwhaGothicB.woff2   # 700

                      CDN 의 index.css 를 <link> 로 직접 참조하면 폰트 요청이 CORS 정책에 막힌다. CDN 이 Access-Control-Allow-Origin 헤더를 보내지 않기 때문이다.

                      파일은 굵기마다 약 1.2~1.3MB 다. font-display: swap 으로 선언되어 있어 폰트를 받는 동안에는 시스템 글꼴로 먼저 그리고, 파일이 없으면 font-family 순서에 따라 Pretendard, 시스템 글꼴로 대체된다. 본문(type-body-*)은 300, 제목은 700 을 쓴다.

                      Vite 는 React Router 의 Link 를 href 를 받는 컴포넌트로 감싸 넘긴다.

                      TSX
                      // src/providers.tsx (Vite + React Router)
import type { ReactElement, ReactNode } from 'react';
import { Link } from 'react-router';
import { HanwhaProvider, ToastProvider, TooltipProvider, type HanwhaProviderProps } from '@nextlab/ds/hanwha';

const RouterLink: NonNullable<HanwhaProviderProps['linkComponent']> = ({ href, ...rest }) => <Link to={href} {...rest} />;

export function Providers({ children }: { children: ReactNode }): ReactElement {
  return (
    <HanwhaProvider syncRoot linkComponent={RouterLink}>
      <TooltipProvider>
        <ToastProvider>{children}</ToastProvider>
      </TooltipProvider>
    </HanwhaProvider>
  );
}

                      HanwhaProvider props

                      prop값기본값설명
                      syncRootbooleanfalseProvider 의 data 속성을 <html> 에도 적용한다. Portal 로 렌더링되는 오버레이에 필요하다. 켜면 DS 리셋이 문서 전체에 적용된다 (3.3)
                      linkComponent컴포넌트<a>Header 메뉴, SiteMenu, SideNavigation, PageTitle 경로, SiteFooter 링크를 그릴 컴포넌트. 라우터의 Link 를 넘기면 페이지를 다시 받지 않고 이동한다
                      textScale"standard" · "large""standard"large 는 type-* 글자 크기와 줄 높이를 1.125배로 키운다
                      colorMode"light" · "dark""light"data-theme 으로 색 토큰 모드를 바꾼다. 다크 토큰은 검토 중 (14장)
                      audience"customer" · "sales""customer"화면 대상. 하위에서 useHanwhaAudience() 로 읽는다

                      TooltipProvider 는 Tooltip 을, ToastProvider 는 useToast() 를 쓸 때 필수다. 없으면 런타임 오류가 난다.

                      2.5Next.js App Router

                      0.9.0 빌드는 React 훅, Context, 이벤트 핸들러, Radix 를 쓰는 모듈에 'use client' 를 자동으로 붙인다. 그래서 Server Component 에서도 DS 컴포넌트를 import 해 렌더링할 수 있다(Next.js 16.4 에서 확인). Graphic, Feedback, Amount, Avatar 처럼 상태가 없는 모듈은 지시어가 없어 서버에서만 그려진다. 다만 'use client' 모듈은 import 하는 모듈 전체를 클라이언트 번들로 가져가므로, Header 나 List 를 쓰는 앱에서는 그래픽 묶음도 클라이언트 번들에 들어간다 (10.3).

                      Next.js 는 Server Component 가 Client Component 에 함수를 props 로 넘기는 것을 허용하지 않는다. 작성 위치는 아래 기준으로 나눈다.

                      작성 위치코드
                      Server Component데이터 조회, 정적 표시(Card List Amount Badge Tag Feedback Graphic 등), href 로 이동하는 링크(<Button asChild><Link href="…">)
                      Client Component ('use client')onClick · onValueChange 같은 이벤트 핸들러, 상태, 폼, useToast(), 오버레이 열기·닫기 제어

                      DS 규칙위치앱 CSS 와 만나면
                      리셋 (preflight)@layer base앱 Tailwind 유틸리티(@layer utilities)가 이긴다. 앱이 준 p-4 가 리셋의 padding: 0 에 덮이지 않는다

                      컴포넌트의 className 이 동작하는 것은 cn()(clsx + tailwind-merge)이 같은 속성의 내부 클래스를 빼 주기 때문이다. h-14 를 넘기면 내부의 h-(--cds-dimension-x12) 가 빠지고 h-14 만 남는다. 상태 변형(data-[state=error]:…)이나 하위 요소 선택자([&_svg]:…)로 걸린 내부 규칙은 빠지지 않고, 레이어 밖이라 넘긴 클래스보다 우선한다.

                      그래서 className 은 배치(margin, width, flex·grid 항목 속성)에만 쓴다. 높이·색·내부 간격을 className 으로 바꾸면 일부 상태에서만 적용되고, 토큰이 바뀌어도 그 화면에는 반영되지 않는다.

                      3.3Portal 과 syncRoot

                      Dialog, BottomSheet, Tooltip, Menu, SelectField 펼침 목록 같은 오버레이는 Radix Portal 로 document.body 아래에 렌더링된다. 이 위치는 Provider 래퍼 밖이라 범위 선택자에 걸리지 않는다. syncRoot 를 켜면 Provider 가 <html> 에 같은 data 속성을 설정해 Portal 내용에도 토큰과 스타일이 적용된다. 앱 루트의 Provider 에는 항상 켠다.

                      syncRoot 는 useLayoutEffect 에서 <html> 의 속성을 바꾸고, Provider 가 사라지면 이전 값으로 되돌린다. 서버 HTML 에는 래퍼 <div> 의 속성이 이미 들어 있으므로 첫 화면은 속성 적용 전에도 스타일이 맞다. <html> 이 범위가 되므로 그 뒤로는 Provider 바깥 요소에도 DS 리셋과 3.6 의 규칙이 적용된다.

                      앱 Tailwind 는 DS 토큰 이름을 모르므로, 토큰 클래스에 변형 접두사를 붙인 조합은 앱에서 생성되지 않는다. DS CSS 에는 DS 소스가 직접 쓰는 조합과 간격 토큰의 md: · lg: 변형만 들어 있다. 그 밖의 조합은 CSS 변수를 참조하는 문법으로 쓴다.

                      6.1구조

                      상호작용 컴포넌트는 Radix UI primitives(Dialog, Select, Tabs, Checkbox, RadioGroup, Switch, Accordion, Tooltip, Popover, Progress) 위에 구현했다. 키보드 조작, 포커스 관리, ARIA 속성은 Radix 의 동작을 따른다. 변형은 class-variance-authority 로 정의하고, 클래스 병합은 cn()(clsx + tailwind-merge)으로 한다.

                      9.1컴포넌트가 처리하는 범위

                      항목동작
                      키보드·포커스Radix 기반 컴포넌트는 방향키 이동, Esc 닫기, 오버레이 포커스 가두기와 복귀를 처리한다
                      펼침 목록PC 의 SelectField 펼침 목록은 WAI-ARIA select-only combobox 패턴이다. 포커스는 칸에 두고 aria-activedescendant 로 줄을 가리킨다. ↑↓ · Home · End · PageUp · PageDown 이동, Enter · Space 선택, Alt+↑ 선택 후 닫기, 글자 입력으로 해당 글자로 시작하는 줄 이동을 지원한다
                      필드 연결label 과 입력 요소를 id 로 연결하고, helpText · errorText 를 aria-describedby 로, 오류 상태를 aria-invalid 로 노출한다

                      12설계 결정과 비용

                      구조를 정한 주요 결정과, 그 결정 때문에 생기는 제약이다. 앞 장의 규칙 대부분이 여기서 나온다.

                      스타일을 미리 컴파일한 CSS 한 파일로 배포한다. Tailwind 설정이나 CSS-in-JS 로 배포하지 않는다앱의 Tailwind 버전·설정과 무관하게 같은 결과가 나온다. 실행 중 스타일 주입이 없어 Server Component 와 스트리밍 렌더링에 제약이 없다. 앱이 토큰을 Tailwind 에 등록하지 않아도 된다쓰지 않는 컴포넌트의 CSS 도 받는다 (10.1). 앱 Tailwind 는 DS 토큰 이름을 몰라 토큰 클래스에 변형 접두사를 붙일 수 없다 (3.5)
                      모든 규칙을 범위 선택자 아래에 둔다기존 앱 CSS 와 한 문서에서 공존하고, 화면 일부에만 적용할 수 있다Portal 은 syncRoot 가 있어야 범위에 든다 (3.3). 선택자 반복으로 원본 CSS 가 커진다 (10.1)
                      리셋만 레이어에 넣고 나머지는 레이어 밖에 둔다앱 CSS 가 무엇이든 컴포넌트 모양이 바뀌지 않는다. 리셋은 @layer base 로 내려 앱 유틸리티를 덮지 않게 했다앱의 변형 클래스가 DS 의 같은 속성 클래스에 진다 (3.6)
                      상호작용은 Radix primitives 위에 만든다키보드·포커스·ARIA 동작을 검증된 구현에 맡기고, 스타일이 없는 primitives 라 Figma 모양을 그대로 입힐 수 있다DOM 구조와 Portal 위치가 Radix 규칙을 따른다
                      토큰은 Figma Variables 에서 생성한다디자이너의 값 변경이 손을 거치지 않고 코드로 넘어오고, 손으로 고친 값은 --check 에 걸린다앱에서 토큰 값을 덮어쓰는 테마 주입을 지원하지 않는다
                      반응형은 토큰이 맡는다글자 크기·간격이 Figma 의 Mobile·Tablet·PC 모드와 같은 분기점에서 바뀌어, 화면 코드에 분기 없이 세 폭이 맞는다토큰은 화면 폭을 따르므로 좁은 영역에 넣어도 글자는 PC 크기다. 영역 폭이 중요한 PageColumns 와 PC Header 만 컨테이너 쿼리를 쓴다
                      아이콘·그래픽은 이름으로 받는다이름이 문자열 리터럴 유니언이라 오타가 타입 오류가 되고, 에디터 자동완성으로 고른다번들러가 쓰는 그림만 골라낼 수 없어 정적 그래픽 묶음이 통째로 들어간다 (10.3)
                      영역이 정해진 컴포넌트는 영역 props 로 받는다영역 순서·간격과 낭독 연결(aria-describedby 등)을 컴포넌트가 보장한다영역 안 배치를 바꾸려면 컴포넌트를 고쳐야 한다
                      'use client' 를 빌드에서 자동으로 붙인다상태가 없는 컴포넌트는 Server Component 로 남고, 상태가 있는 컴포넌트도 Server Component 에서 바로 import 할 수 있다함수 props(onClick 등)는 Server Component 에서 넘길 수 없다 (2.5)
