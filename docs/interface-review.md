# 제품 소개 페이지 수정 및 검증 · 2026-09-22

## 디자인 기준

기존 페이지의 큰 제목, 어두운 배경, 오렌지 Builder·바이올렛 Studio 색상과 입체적인 제품 배치를 기준으로 다시 구성했습니다. 첫 수정의 일반적인 작업 공간·다운로드 중심 구성을 변경해 두 제품의 역할과 실제 결과물이 소개의 중심이 되도록 했습니다.

- 히어로: Builder 검증 결과와 현재 Studio 디자인 캔버스를 함께 배치.
- Builder: Figma 원본·실제 렌더 결과 비교, 코드 편집, 개발표준 관련 기능.
- Studio: 실제 프로젝트의 디자인·기능명세·User Flow를 전환해 확인.
- 설치·가이드: 각 제품 소개와 하단에서 연결. 버전과 파일 링크는 배포 메타데이터 사용.
- 테마: 기존 다크 화면을 기본으로 유지. 라이트 모드도 같은 조판과 제품별 색상을 사용하고 선택을 저장.

## 확인한 범위

홈, 다운로드, Studio 다운로드, 가이드 목록, 두 상세 가이드, 업데이트의 7개 페이지입니다. 인쇄용 HTML은 브랜드의 대문자 표기만 통일했습니다. PDF/PNG 소개 자료는 범위에 포함하지 않습니다. Studio 캡처는 개발 중인 실제 화면이며 설치 버전과 차이가 있을 수 있다는 안내를 제공합니다.

## 검증 결과

- 정적 검사: 7개 페이지, 로컬 링크·앵커·이미지, Studio 캡처 10개, 릴리스 메타데이터 정상.
- 자동 접근성: 7개 페이지의 라이트·다크 모드에서 axe WCAG A/AA 위반 0건.
- 화면 크기: 320·390·768·1024px에서 7개 페이지 가로 넘침 없음. 홈은 600·720·1440px도 확인.
- 실제 브라우저: 두 테마의 전체 홈, 모바일 홈·제품 소개, 다운로드·가이드 화면을 확인.
- 테마 선택 유지: 새로고침·페이지 이동, 저장소 차단 환경의 전환 정상.
- Studio 미리보기: 3개 탭, 방향키·Home·End, 확대 후 Escape와 초점 복귀 정상.
- 설치: 메타데이터와 링크 일치, 실패 후 재시도, 일부 플랫폼 미제공 상태 정상.
- 모바일 메뉴, FAQ, 이전 업데이트 펼치기, JavaScript 비활성화 대체 링크, 동작 줄이기 정상.
- JavaScript 구문 및 `git diff --check` 정상.

Playwright와 axe-core는 로컬 `nextlab-ai`에 설치된 도구를 사용했습니다. 개발 의존성을 추가하지 않았습니다. 자동 접근성 검사는 제품 디자인 평가를 대신하지 않으며, 시각 구성은 위의 디자인 기준으로 별도 확인했습니다.

실제 설치 프로그램 실행, Safari·Firefox 검사, 운영 배포는 수행하지 않았습니다. 커밋·푸시는 수행하지 않았습니다.

## 브랜드와 대표 화면 추가 수정

- 모든 웹 페이지의 노출 브랜드명을 `NEXTLAB` 대문자로 통일했습니다. 설치 파일명·배포 URL은 기존 릴리스와 일치하도록 유지했습니다.
- 제공받은 Builder·Studio 로고 네 개를 제품 소개·다운로드·가이드에 적용했습니다. CSS로 여백과 테마별 배경을 맞추었으며 원본 JPG는 변경하지 않았습니다.
- 제목 앞 막대, 상태 점, 가짜 창 버튼과 불필요한 영문·순번 장식을 제거했습니다.
- 두 상세 가이드의 왼쪽 목차를 짧은 기능명으로 정리했습니다.
- LIFEPLUS SELECT 멤버십 홈을 직접 제작하고 Studio의 새 작업 공간 518에 저장했습니다. 이미지 구도·텍스트·여백·반응형 배치와 한글 레이어 이름을 보정한 실제 편집 화면을 두 테마로 촬영했습니다.
- 원본은 `examples/studio-membership/`에 남겼습니다. 검색·필터·저장·상세 팝업·모바일 메뉴가 동작하며, 예약과 결제는 제공하지 않는 시안입니다.
- 새 시안의 6개 화면 너비, 주요 상호작용, 데스크톱·모바일 axe WCAG A/AA를 확인했습니다.

## 2026-09-23 · 예제 교체와 하단 구성 보강

- 기획·기능명세와 User Flow를 가상 서비스 ‘주말의 발견’으로 교체했습니다. 원본 기획 문서와 네 화면은 examples/weekend-discovery/에 보관합니다.
- 새 Studio 프로젝트 559와 연결 디자인 560에 직접 작성한 예제를 저장하고 촬영했습니다. User Flow의 시작·완료 노드와 기능 연결을 점검해 구조 경고 0건을 확인했습니다.
- Studio 개별 도구 영역을 문구·이미지 활용·컴포넌트 구현 예시와 도구별 설명·가이드 링크로 구성했습니다.
- 7개 웹 페이지의 공통 푸터를 제품·시작하기·사용 안내 메뉴와 큰 NEXTLAB 워드마크로 확장했습니다.
- 7개 페이지 × 2개 테마에서 axe WCAG A/AA 위반 0건, 320·390·768·1024px에서 가로 넘침 0건을 확인했습니다.
- 예제의 네 화면 이동, 날짜·시간 선택의 결과 화면 반영, 320·390·768·1440px 레이아웃을 확인했습니다.

### 하단 스타일 캐시 수정

- 오래된 CSS가 캐시에 남으면 새 HTML의 도구 카드·푸터가 일반 블록으로 표시되는 현상을 브라우저 캐시 시나리오로 재현했습니다.
- 공통 CSS/JavaScript URL에 내용 해시를 넣어 변경된 자산을 새로 요청하도록 수정했습니다. `scripts/version-assets.mjs`로 갱신하며 정적 검사에서 해시 불일치를 검출합니다.
- 같은 브라우저 캐시를 유지한 상태에서 수정 전의 배치 붕괴와 수정 후의 그리드 복원을 확인했습니다. localhost:3300에서도 버전이 적용된 스타일을 정상 로드합니다.

### 이미지 캐시와 프로토타입·개발 소개

- 이미지도 내용 해시로 버전 관리합니다. 갤러리의 동적 이미지 주소를 탭의 `data-light-src`·`data-dark-src`에서 읽도록 바꿔 본문·테마 전환·확대 화면이 같은 파일을 사용합니다.
- 같은 브라우저에 오래된 이미지 네 장을 캐시한 뒤, 버전 적용 후 최신 기획·User Flow 이미지로 모두 교체되는 것을 확인했습니다. localhost:3300에서 받은 다섯 종류 × 두 테마 이미지의 해시도 원본과 일치합니다.
- 실제 Studio의 프로토타입·개발 화면을 두 테마로 촬영하고, 메인 갤러리를 다섯 탭으로 확장했습니다. 프로토타입·개발 상세 소개와 현재 사용 가이드도 추가했습니다.
- 새 예제는 Studio에서 네 화면의 시나리오를 건너뛰지 않고 완료했습니다. 개발 프로젝트는 Studio 조립 후 코드 문법·타입·앱 빌드 검사를 통과했으며 서버 예약 기능은 포함하지 않습니다.
- 변경된 홈·Studio 가이드의 두 테마에서 axe WCAG A/AA 위반 0건, 320·390·520·600·768·1024px 가로 넘침 0건을 확인했습니다. 다섯 탭의 방향키·Home/End·확대·Escape·초점 복귀도 확인했습니다.

### 후속 구성 정리

- Studio 소개는 기획·기능명세 → User Flow → 화면 디자인 → 프로토타입 → 개발 순서이며, 첫 화면도 기획입니다.
- 사용자 피드백에 따라 7개 페이지의 대형 푸터 워드마크와 장식 화살표를 제거했습니다. 작은 NEXTLAB 표기, 제품·설치·사용 안내 메뉴, 저작권 정보로 정리하고 전체 높이를 줄였습니다.

### 다운로드 UI 개편

- 메인 하단의 설치 영역, 전체 다운로드 페이지, Studio 전용 다운로드 페이지를 다시 구성했습니다. 제공된 제품 로고, Studio 보라색·Builder 주황색, 기존 두 테마를 공통으로 사용합니다.
- 전체 다운로드에서는 제품을 나란히 비교하고 Studio의 macOS Apple Silicon·Intel·Windows 파일 또는 Builder의 VSIX 파일을 선택합니다. 모바일에는 제품 바로가기와 세로형 다운로드 버튼을 제공합니다.
- Studio 전용 페이지는 실제 디자인 캔버스와 설치 파일 선택을 첫 영역에 배치했습니다. 설치 순서·칩 확인·문제 해결은 필요한 안내를 펼쳐 읽습니다.
- 버전·링크·파일 크기는 기존 배포 메타데이터를 그대로 읽습니다. 로딩 실패·재시도·일부 파일 누락 시에도 운영체제 이름과 버튼 구조가 유지되도록 수정했습니다.
- 세 화면의 두 테마에서 axe WCAG A/AA 위반 0건, 320·390·600·720·768·928·1024·1440·1920px에서 가로 넘침 0건을 확인했습니다. 데스크톱과 모바일 캡처를 직접 검토했습니다.
- 실제 메타데이터와 설치 링크 일치, 실패 후 재시도, 누락·허용되지 않은 다운로드 주소 차단, 키보드로 설치 안내 펼치기, 앵커 이동·재진입, JavaScript 미사용 시 대체 링크를 확인했습니다. RTL 방향 전환에서도 두 다운로드 페이지의 모바일 가로 넘침이 없었습니다.
- 공통 스크립트 변경 후 7개 페이지에서 JavaScript 오류가 없었으며 정적 링크·이미지·자산 해시 검사도 통과했습니다. 실제 설치 프로그램 실행과 Safari·Firefox는 확인하지 않았습니다. 커밋·푸시하지 않았습니다.
